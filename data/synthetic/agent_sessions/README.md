# Synthetic agent sessions

Fictional coding-agent sessions for scoring exchange labelers before any real
session text is used. Everything here is generated by
`scripts/generate_synthetic_data.py` (fixed seed, byte-identical on re-run)
except this README.

## Layout

```
agent_sessions/
  -work-acme-ledgerline/        one directory per fictional repo, named the
  -work-acme-metering-api/      way Claude Code encodes a working directory
  -work-acme-docs-site/
    <session-uuid>.jsonl        a root session
    <session-uuid>/subagents/
      agent-<id>.jsonl          a subagent transcript (its sessionId field is
      agent-<id>.meta.json      the parent's; identity comes from the path)
  rules_history.jsonl           rules in force per repo, with effective dates
```

Transcripts use Claude Code's entry shapes. Each assistant content block is its
own entry sharing one message id, as the client writes them, and tool results
arrive as user entries.

## What a labeler is scored on

A unit is a typed reply: a user entry whose content is text the person typed,
judged with the typed prompt before it. The key in
`../eval/exchange_labels.jsonl` answers four questions for every unit:

| Question | Type | Key rows |
|---|---|---|
| `user_response` | choice | every unit |
| `correction_kind` | choice | only units whose `user_response` is `correct` |
| `rule_violated` | choice | every unit; options are the repo's rules in force on the session date, sorted by id, then `none` |
| `frustration` | score, 0 to 2 | every unit |

Key rows carry `labeler_kind` `key`, `labeler` `synthetic`, no probability and
no `input_content_hash`. Join them to a labeler's rows on
`(native_session_id, user_entry_uuid, question_id, question_version)`.
`options_hash` is sha256 of the ordered `[label, description]` pairs as compact
JSON in UTF-8 (`freud_schema.ingest.options_hash`).

Every planted answer is readable from the reply alone.

## Entries that are not units

These appear in the sessions so a typed-reply filter is actually exercised, and
no key row names any of them:

- tool-result carriers (user entries whose content is a list of tool results)
- meta entries (`isMeta: true`)
- slash-command output (`<command-name>`, `<local-command-stdout>`)
- hook reminder injections (`<system-reminder>`)
- compact summaries (`isCompactSummary: true`)
- interruption markers (`[Request interrupted by user]`); the typed reply after
  one is a normal unit
- everything in subagent transcripts, whose "user" is the orchestrating agent
- the opening prompt of each session, which has no assistant turn before it

## Rule history

`rules_history.jsonl` has one row per rule version: `project_dir`, `rule_id`,
`statement`, `effective_from`, `effective_to` (null while in force). Some rules
start, change or retire mid-period. A reply dated before a rule took effect is
keyed `none`, even when it complains about exactly what the rule later covers.
